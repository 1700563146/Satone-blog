# 照片墙：照片格式与体积

照片墙的图片直接放在 `public/wall/`，构建时不做二次处理（Astro 只会原样拷贝），
所以**图片本身的体积就是用户要下载的体积**。下面这套流程能把体积压到原来的 1/5 左右，
同时保持"点开能看清"的画质。

## 一句话结论

| 用途 | 格式 | 长边 | 质量 | 典型体积（真实照片） |
|---|---|---|---|---|
| 照片墙 / 相册（推荐） | **WebP** | 1600px | q78 | 80–200 KB |
| 想要更省 | AVIF | 1600px | q60 | 50–140 KB（兼容性略差） |
| 需要老设备兜底 | JPEG | 1600px | q82 | 150–350 KB |

> 本项目选 **WebP**：Chrome / Edge / Safari 14+ / Firefox 65+ 全部支持，
> 压缩率比 JPEG 好 25–35%，又不像 AVIF 那样在低端机上解码偏慢。

## 工作流

```bash
# 1. 原图丢进 wall-src/（已在 .gitignore 里，不会进仓库）
# 2. 批量转 WebP，输出到 public/wall/
pnpm wall:opt

# 可选：同时输出 AVIF（想要 <picture> 双格式时用）
pnpm wall:opt --avif

# 可选：调整尺寸/质量
WALL_MAX_EDGE=2000 WALL_QUALITY=82 pnpm wall:opt

# 可选：输出到指定子目录（示例图就是这么生成到 public/wall/demo/ 的）
WALL_OUT=public/wall/demo pnpm wall:opt
```

脚本会打印每张的「原图 → 输出」体积对比，最后给出总节省比例。
文件名会自动小写、空格和下划线转成连字符。

## 在配置里登记

```ts
// src/config/photoWallConfig.ts
photos: [{ src: "/wall/demo/night-1.webp", caption: "…", meta: "…" }]
```

## 为什么这样最省

1. **长边 1600px 够用**：灯箱里最大也就显示到 ~1400 CSS px（`max-width: min(92vw, 1400px)`），
   1600 的长边在 2× 屏上依然清晰，再大只是白给流量。
2. **相册列表用同一张图**：每摞照片只加载封面等 3 张（`loading="lazy"`），
   没有额外的缩略图请求；一个 3 张的相册首页只多 3 个请求、合计几十 KB。
3. **不重复出图**：相册页和灯箱用同一个 `src`，浏览器缓存命中，点开不会二次下载。
4. **不用大图做背景**：没有任何全屏背景图，避免首屏就吃几百 KB。

## 实测（仓库自带的 9 张示例图）

```
JPEG q86 1200×900：0.70 MB
WebP q78 长边 1600：0.11 MB   ← 省 83%
```

示例图是程序生成的渐变+噪点，属于"特别好压"的类型；真实照片大概落在
**120 KB / 张（1600px WebP）** 这个量级，一个 10 张的相册约 1.2 MB，
配合懒加载，首屏只会先拉 3 张（≈360 KB）。

## 如果以后想更极致

- 用 Astro 的 `<Image />`（`src/assets` 导入）让构建期生成多尺寸 `srcset`，
  手机拿 800px、桌面拿 1600px —— 代价是 `public/wall/` 那套"丢图即可用"的简单流程要改；
- 给 `<img>` 加 `srcset="….webp 1600w, ….webp 800w"`（脚本可以顺手多输出一个 800px 版本）；
- 真正的长列表再考虑缩略图 + 灯箱大图分离。
